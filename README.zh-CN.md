# osu!mania Inverse Converter

中文 | [English](README.md)

[![Language: C](https://img.shields.io/badge/Language-C99-blue.svg)]()

一个轻量化的 osu!mania 谱面转换小工具，可将谱面中的普通音符（Rice）转换为长条（LN），或将 LN 删除、保留、拉长或全部转Rice。  
转换时可为生成的长条预留可自定义长度的间隙（gap），满足不同反键（Inverse）玩法需求。

---

## ✨ 功能特性

- ✅ 轻量化：单文件 C 程序，无外部依赖，运行快速
- ✅ 可自定义间隙长度（默认 1/4 拍，可设为 1/8、1/2、1/16 等）
- ✅ 四种 LN 处理模式：保留、拉长、删除、全部转 Rice
- ✅ 支持变速谱面（根据红线自动计算 BPM）
- ✅ 支持 1K ~ 18K 所有键位
- ✅ 支持批量处理多个 .osu 文件
- ✅ 输出文件自动命名，并在难度名后添加转换标记

## 🔧 转换规则

### 普通音符（Rice）

对于每个 Rice，程序会查找**同一列**的下一个对象（可能是 Rice 或 LN）：

- 若与下一个对象间隔 ≥ 1/N 拍且生成的 LN 长度 ≥ 10 ms，则将该 Rice 转换为 LN。
- 若不满足条件或没有下一个对象，则保留为 Rice。

### 已有长条（LN）处理模式

可选择以下四种模式之一：

#### 模式 0：保留（keep）
原有 LN 完全不改动。

#### 模式 1：拉长（extend）
如果 LN 的结尾与同列下一个对象之间的间隔大于自定义间隙长度，则将该 LN 的结束时间延长，使间隙等于自定义长度；否则保持原样。

#### 模式 2：删除（delete）
删除所有原始 LN，并判断：

- 对于每个原始 LN，查找同列前一个物件。
  - 若前一个物件是 LN：将其结束时间延长到当前 LN 的开始时间。
  - 若前一个物件是普通 note：
    - 如果间隔 ≥ 10 ms，则将该普通 note 转换为 LN，结束时间为当前 LN 的开始时间。
    - 如果间隔 < 10 ms，则保留普通 note 不变。
- 删除当前 LN。
- 在当前 LN 的结束点添加一个新物件：
  - 如果结束点与同列下一个物件的间隔 ≥ gap 且新 LN 长度 ≥ 10 ms，则添加一个新 LN（开始时间 = 原 LN 结束点，结束时间 = 下一个物件时间 - gap）。
  - 否则，添加一个普通 note。
- 处理完所有原始 LN 后，再对剩余的普通 note 执行模式 0 的 Rice→LN 转换。

效果：玩家在原始 LN 的头部和尾部松手，其余时间按住。

#### 模式 3：全部转 Rice（rc）
将所有 LN 转换为 Rice，其他物件保持不变。

## 📦 编译

### Windows (MinGW / MSYS2)

```bash
gcc -Wall -O2 -o osuInverseConverter.exe osuInverseConverter.c -lcomdlg32 -lm
```

### Linux / macOS

```bash
gcc -Wall -O2 -o osuInverseConverter osuInverseConverter.c -lm
```

> 注意：非 Windows 平台仅支持命令行参数模式，不支持文件选择对话框和消息框。

## 🚀 使用方法

### 1. 交互模式（仅 Windows）

双击 `osuInverseConverter.exe`，程序会依次询问：

1. **gap 除数**：输入正整数（如 `4` 表示 1/4 拍，`8` 表示 1/8 拍），或直接输入 `rc` 进入模式 3（将所有 LN 转为普通 note）。
2. **LN 处理模式**（若未输入 `rc`）：输入 `0`、`1`、`2` 分别代表保留、拉长、删除。

然后弹出文件选择对话框，选择 `.osu` 文件后自动转换，完成后弹出提示框。

### 2. 拖拽模式（仅 Windows）

将一个或多个 `.osu` 文件拖拽到 `osuInverseConverter.exe` 图标上，程序会打开控制台窗口，直接询问 gap 除数和 LN 处理模式。输入后自动批量转换所有文件，完成后弹窗显示处理数量。

### 3. 命令行批量处理

```bash
osuInverseConverter.exe [-gap <n>] [-mode <m>] 文件1.osu [文件2.osu ...]
```

- `-gap <n>`：设置 gap 除数（正整数），可省略，默认 `4`。
- `-mode <m>`：设置 LN 处理模式（`0`、`1`、`2`、`3`），可省略，默认 `0`。
- 快捷方式：直接使用 `rc` 作为参数，等价于 `-mode 3`。
- 示例：
  ```bash
  # 使用 1/8 拍间隙，模式 2（删除 LN）
  osuInverseConverter.exe -gap 8 -mode 2 song1.osu song2.osu

  # 使用默认 1/4 拍间隙，模式 1（拉长 LN）
  osuInverseConverter.exe -mode 1 song.osu

  # 将所有 LN 转为普通 note
  osuInverseConverter.exe rc song.osu
  ```

## 📁 输出文件

转换后的文件保存在原谱面同目录下，文件名为：

- 模式 0/1/2：`原文件名 (inverse 1-N).osu`  
- 模式 3：`原文件名 (rc).osu`

谱面内的难度名（`Version` 字段）会相应添加 ` (inverse 1/N)` 或 ` (rc)` 标记。

例如，输入 `song.osu`，使用 gap 除数 8，输出文件为 `song (inverse 1-8).osu`，难度名变为 `原来的难度名 (inverse 1/8)`；若输入 `rc`，则输出 `song (rc).osu`，难度名为 `原来的难度名 (rc)`。

## ❓ 常见问题

**Q: 为什么有些 Rice 没有转换？**  
A: 可能原因：与下一个同列对象的间隔不足 gap；生成的 LN 长度小于 10 ms；该音符是所在列的最后一个对象；运算可能存在浮点数误差。

**Q: 如何处理变速？**  
A: 程序解析所有红线（uninherited timing points），根据音符所在时间点的 BPM 计算 gap，能正确适应变速谱面。

**Q: 如何指定 1/8 拍间隙？**  
A: 交互模式或拖拽时输入 `8`；命令行使用 `-gap 8`，例如 `osuInverseConverter.exe -gap 8 file.osu`。

**Q: 程序会修改原文件吗？**  
A: 不会，原文件保持不变，输出为新文件。

**Q: 命令行参数格式是什么？**  
A: 支持显式参数：`-gap <n>` 设置 gap 除数，`-mode <m>` 设置 LN 模式（0/1/2/3）。也支持 `rc` 快捷方式，等价于 `-mode 3`。参数顺序不限，文件列表跟在参数之后。  
例如：  
`osuInverseConverter.exe -gap 8 -mode 2 song.osu`  
`osuInverseConverter.exe rc song.osu`

**Q: 如何选择 LN 处理模式？**  
A: 交互模式或拖拽模式中，程序会询问 `Process existing LNs? (0 = keep, 1 = extend, 2 = delete)`。命令行使用 `-mode` 参数，例如 `-mode 2`。

**Q: 为什么编辑器总是提示“物件结尾没有对齐时间轴”？**  
A: 转换时，程序根据当前 BPM 计算 LN 的结束时间。由于运算常常出现小数，造成的浮点误差可能导致计算出的结束时间不会完全落在编辑器的节拍网格上，通常误差都在1ms内。如果希望谱面在编辑器中显示整齐，可以在转换后使用编辑器自带的“全部重新对齐”功能。
